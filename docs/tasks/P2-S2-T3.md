## Why this model / review tier
Sonnet: builds on the existing `createOrderWithToken` helper.
Opus review: this deliberately releases PDFs without the automatic checks, so it must be impossible to trigger by accident or from outside admin.

## Context
`createOrderWithToken(env, {paymentId|null, versionId, createdBy, adminNote, now})` exists in `src/lib/claim.ts` and returns the raw token. Download tokens are stored only as hashes, so **a new link is shown once** and can't be shown again. The payment detail page has `<section id="actions">`. The `/admin/orders` stub router exists.

## Do this
1. Actions on the payment detail (`payment-actions.tsx`, rendered into `#actions`):
   - For `unclaimed` or `flagged` payments: "Approve for…" a version dropdown + required note + a confirm checkbox "I checked this payment is real" → `POST /admin/orders/approve-payment`. In one batch: `UPDATE payments SET status='claimed', claimed_at=?, claim_ref=? WHERE id=? AND status IN ('unclaimed','flagged')`, then the order (`created_by='admin'`, note) + token, guarded by `claim_ref` exactly like the auto-claim. If 0 rows changed → error "Payment was already claimed".
2. `GET/POST /admin/orders/manual`: "Approve without a payment" (SMS lost or bank-app payment, FR-26): version + required note (e.g. the buyer's txn and contact) + confirm → order with `payment_id NULL` + token.
3. `POST /admin/orders/:id/regenerate`: set `revoked_at=now` on all of the order's tokens, then create a new token (batch). Add a **New link** button per row in `orders-list.tsx` and on the payment detail, plus an **Approve without a payment** button at the top of `orders-list.tsx` linking to `/admin/orders/manual`.
4. After any of the three: render `link-created.tsx` with the full download URL, a Copy button, and "This link is shown only once. Send it to the buyer now (Telegram/SMS)." Use `Cache-Control: no-store`.
5. Refactor `src/lib/claim.ts` only as needed to share the batch logic. **The auto-claim behaviour and its tests must not change.**
6. Log `{event:"admin_approve"|"admin_manual_order"|"admin_regenerate", orderId}`.

## Acceptance criteria
- Approving a flagged `DEMOLOW001` for Sealion → the payment is `claimed`, the order has `created_by='admin'` and the note, and the shown link downloads the PDF (FR-26).
- Approving an already-claimed payment → error, no new order.
- A manual order without a payment works and appears in the orders list as "manual".
- Regenerate → the old link returns 410 and the new link works with a fresh 3-download allowance.
- All three actions reject requests without the confirm checkbox and note, and reject a foreign `Origin` (via admin auth).
- All Phase 1 claim tests still pass unchanged.

## Tests to write or update
- `test/admin-approve.test.ts`: the cases above, including a race between an auto-claim and an admin approve for the same payment (exactly one wins).

## How to test manually
1. `pnpm db:reset:local && pnpm seed:local`, then `pnpm dev` (public :8787) and `pnpm dev:admin` (admin :8788)
2. On the public site, try `DEMOLOW001` on Sealion → amount too low.
3. http://localhost:8788/admin/payments?status=flagged → open `DEMOLOW001` → Approve for Sealion with note "paid rest in cash" → copy the link → it downloads.
4. `/admin/payments/orders` → Regenerate on that order → the old link shows "expired or used up"; the new one works.
5. `/admin/orders/manual` → create a manual order for E2 → its link works.
