## Why this model / review tier
Sonnet: real feature work: queries, visibility rules, two pages and an image route.
Auto: read-only public pages; no payment or personal data.

## Context
Schema and row types exist (`src/lib/db/types.ts`). Route stubs `publicRoutes` (mounted at `/`) and `apiRoutes` (mounted at `/api`) exist. `Layout` and `santimToEtbLabel` exist. Vars: `TELEBIRR_PHONE`, `TELEBIRR_NAME`, `SUPPORT_CONTACT`. The claim form behaviour comes in P1-S3-T3; this task only renders its markup.

**Design:** build both pages to match `docs/design.md` and the reference screens `docs/design/catalog-mobile.dc.html`, `docs/design/catalog-desktop.dc.html` (the catalog is one responsive page) and `docs/design/checkout-mobile.dc.html` (page structure only; the claim states are P1-S3-T3). Use the classes from `app.css`; add page-specific CSS there only if needed. The car outline SVG, icons and copy come from the reference files.

## Do this
1. `src/lib/db/catalog.ts`:
   - `listCatalog(db)` → visible models ordered by `sort_order, name`, each with its visible `en` version and `available = r2_key IS NOT NULL`. A model with no available version is returned with `available: false` (FR-3).
   - `getCheckout(db, slug)` → the visible model + its visible version, or `null` if the model is missing or hidden. Use a single JOIN query.
2. `GET /` (catalog, FR-1/FR-2/FR-3): hero, "How it works" (3 steps; the dark card at ≥ 900px), the manuals grid, the trust notes, and the FAQ, as in the references. A card per model with image (`/media/images/<key>` or `/img/car-placeholder.svg`), name, "<model_year> · English owner's manual", price "500 ETB", a dark "Get manual" link to `/m/<slug>`. Unavailable models show the "Coming soon" pill and a "Translation in progress" block instead of the link.
3. `GET /m/:slug` (checkout, FR-4/FR-5). 404 page if `getCheckout` returns null **or** the version is unavailable. Content, in this order:
   - Back link "All manuals"; the model tile + "<name> (<year>)" + "English owner's manual · PDF" (append " · N MB" if `file_size` is known).
   - The dark price card, then the "Pay with telebirr" card with numbered steps: (1) Open the **telebirr app**. (2) Send exactly **<price>** to: the phone box with `TELEBIRR_PHONE` formatted `0977 328 406` in mono, "telebirr shows: **<TELEBIRR_NAME>**", and a Copy button (`data-copy="<digits>"`, handled by `public/js/copy.js`: copies, shows "Copied" for 1.6 s, works without errors if the clipboard API is missing). (3) In the telebirr app, find the **transaction number** of this payment. (4) Enter it below to get your PDF.
   - Warn notice: "**telebirr to telebirr only.** Payments from a bank app can't be verified automatically."
   - Claim form: `<form id="claim-form">` with label "Transaction number", `input#txn` (name `transactionNumber`, `placeholder="D•••••••••"`, `autocapitalize="characters"`, `autocomplete="off"`, `inputmode="text"`, `maxlength="14"`, `aria-describedby="txn-hint"`), `<p id="txn-hint">Copy it from the telebirr app. It starts with D and has 10 letters and numbers.</p>`, hidden `versionId`, a `<div id="turnstile-slot"></div>` (used in P3), a submit button "Get my PDF", and `<div id="claim-status" aria-live="polite"></div>`. Add `<script type="module" src="/js/claim.js">`.
   - "Paid but something went wrong?" section: "Email <SUPPORT_CONTACT> with your transaction number and the model you bought. We'll sort it out by hand."
4. `GET /api/models` → JSON per `architecture.md` §5: `[{slug, name, modelYear, imageUrl, versions:[{id, language, priceEtb, available}]}]` (`priceEtb` is a number in ETB).
5. `GET /media/images/*` → stream from R2 `MANUALS` only when the key starts with `images/`, with its stored content type and `Cache-Control: public, max-age=86400`; 404 otherwise. **Never serve keys under `manuals/` from this route.**
6. `public/img/car-placeholder.svg`: the outline car drawing from the reference files (stroke `--faint`), used whenever a model has no uploaded image.

## Acceptance criteria
- Catalog shows visible models in sort order with "500 ETB"; Dolphin shows "Coming soon" without a link; hidden Han is absent (FR-1, FR-3).
- `/m/byd-sealion-2026` shows the price, phone, name, 4 numbered steps, the telebirr-only notice, and the transaction-number hint (FR-4, FR-5).
- The hint is display-only: validation stays "10 letters/digits" and does **not** require a leading D (prefixes appear to change over time: DI… in Sept, DJ… in Oct 2026).
- `/m/byd-han-2024` (hidden), `/m/byd-dolphin-2025` (no PDF) and `/m/unknown` → 404.
- `/api/models` returns the documented shape; hidden models are absent.
- `/media/images/manuals/x.pdf` → 404.
- No payer data or R2 `manuals/` keys appear in any HTML or JSON.
- At 390px and 1280px wide, the pages match the reference screens in layout, type, colours and copy (spot-check side by side). No horizontal scrolling at 360px.
