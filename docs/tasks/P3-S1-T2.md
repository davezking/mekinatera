## Why this model / review tier
Sonnet: CSP needs judgment so it doesn't break Turnstile or the admin upload script.
Auto: headers and pages; tests catch regressions.

## Context
`src/index.ts` already sets `X-Robots-Tag` outside production. Admin and download routes set their own `no-store`/`noindex`. Turnstile loads from `challenges.cloudflare.com` (P3-S1-T1, which runs in parallel and does not touch these files). All JS and CSS are self-hosted under `/js` and `/css`.

## Do this
1. `src/middleware/security.ts` (applied globally in `src/index.ts` **and** `src/admin-worker.ts`):
   - `Content-Security-Policy: default-src 'self'; script-src 'self' https://challenges.cloudflare.com; frame-src https://challenges.cloudflare.com; connect-src 'self'; img-src 'self' data:; style-src 'self'; font-src 'self'; base-uri 'none'; form-action 'self'; frame-ancestors 'none'`
   - `X-Content-Type-Options: nosniff`, `Referrer-Policy: strict-origin-when-cross-origin` (downloads keep `no-referrer`), `Permissions-Policy: camera=(), microphone=(), geolocation=()`.
   - In production also `X-Robots-Tag: noindex` for `/d/*` (other envs keep the global noindex; the admin Worker is always noindex).
2. `public/robots.txt`: allow `/`, disallow `/admin`, `/d/`, `/api/`.
3. `src/views/error.tsx` + `app.notFound` and `app.onError` in `src/index.ts`: friendly HTML 404/500 for page routes and JSON `{error}` for `/api/*`. `onError` logs `{event:"unhandled_error", path, message}`. **No request bodies, headers or stack traces with user data.**
4. Grep the codebase for `console.` and fix any log line that could include payer name, phone, SMS body, token, ticket or secret (list the changes in the PR).

## Acceptance criteria
- Every HTML response carries the CSP and the other headers; the checkout page still renders Turnstile with no CSP violations in the console.
- Admin upload, claim polling and download still work under the CSP (inline scripts and styles are not used anywhere).
- `/robots.txt` is served; unknown pages → friendly 404; a thrown error → friendly 500 with no stack trace in the body.
- No log statement can output personal data or secrets.

## Tests to write or update
- `test/security.test.ts`: headers on `/`, `/m/<slug>`, `/api/models` (via `SELF`) and `/admin` (via `adminFetch`); robots.txt; 404 HTML vs JSON; `onError` body has no stack trace.

3. Open `/does-not-exist` → friendly 404 page.
