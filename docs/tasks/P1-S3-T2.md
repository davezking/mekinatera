## Why this model / review tier
Sonnet: the algorithm is specified; the work is streaming and Range handling.
Opus review: this is the only gate between the public and the private PDFs.

## Context
Tokens are created by `src/lib/claim.ts`; `hashToken` is in `src/lib/token.ts`. `downloadRoutes` is mounted at `/d`. PDFs are in R2 binding `MANUALS` at `manual_versions.r2_key`. Algorithm: `architecture.md` §5 "Download algorithm".

## Do this
1. `GET /:token`:
   - Reject anything that isn't base64url with 43 characters → 410 page (do not hit the DB).
   - Look up by `token_hash` joined to order → manual version → car model.
   - Not found, `revoked_at` set, `expires_at <= now`, or `download_count >= max_downloads` → 410 HTML page (`src/views/download-error.tsx`), built to match `docs/design/link-expired-mobile.dc.html`: icon tile, "This download link has expired", "Links work for 24 hours and up to 3 downloads. This one has run out, or a new link was sent to you.", the "Already paid?" card with the support email, and a dark "Back to manuals" button (FR-19).
   - Parse `Range: bytes=start-end?`. If there is no Range header, or `start === 0`, run the atomic increment (`UPDATE … WHERE id=? AND download_count<max_downloads AND expires_at>? AND revoked_at IS NULL`) and return 410 if `changes !== 1`. Ranges with `start > 0` (resumed downloads) skip the increment but still require a valid, unexpired, unrevoked token.
   - `MANUALS.get(r2_key, range ? { range } : undefined)`. If missing → 500 page + log `{event:"r2_missing", versionId}`.
   - Stream `object.body`. Headers: `Content-Type: application/pdf`, `Content-Disposition: attachment; filename="BYD-<Name>-<Year>-EN.pdf"` (ASCII, spaces → `-`), `Content-Length`, `Accept-Ranges: bytes`, `Cache-Control: private, no-store`, `X-Robots-Tag: noindex`, `Referrer-Policy: no-referrer`. For ranges: 206 + `Content-Range`.
   - **Never** call `arrayBuffer()`/`text()` on the object (FR-20, free-plan rule).
   - Log `{event:"download", orderId, count}` only.

## Acceptance criteria
- A valid token → 200 PDF with the right filename; `download_count` becomes 1 (FR-18, FR-20).
- Three full downloads succeed; the fourth → 410 (FR-19).
- `expires_at` in the past → 410; `revoked_at` set → 410.
- `Range: bytes=100-` → 206 with `Content-Range`, and the count does not increase.
- A malformed token (`/d/abc`) → 410 without a DB query.
- There is no route that serves an R2 `manuals/` object without a token.

## Tests to write or update
- `test/download.test.ts`: create an order and token via `createOrderWithToken`, put a small PDF in the test R2, then assert all of the criteria above, including the count after each request.

## How to test manually
1. Get a `downloadUrl` as in P1-S3-T1's manual test.
2. Open it in a browser → the demo PDF downloads as `BYD-Sealion-2026-EN.pdf`.
3. Open it 3 more times → the 4th shows the "expired or used up" page.
4. `curl -s -o /dev/null -w '%{http_code}' localhost:8787/d/abc` → 410.
