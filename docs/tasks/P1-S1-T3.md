## Why this model / review tier
Haiku: a mechanical script; the data and commands are spelled out below.
Auto: it never touches production (enforced) and only writes demo data.

## Context
Schema exists (`migrations/0001_init.sql`, types in `src/lib/db/types.ts`). `package.json` already has `seed:local` / `seed:staging` running `tsx scripts/seed.ts --env <env>`. CI runs `pnpm seed:staging` after every staging deploy. Wrangler v4 needs an explicit `--local` or `--remote` on `d1 execute` and `r2 object put`.

## Do this
1. `scripts/seed.ts` (Node, run with tsx):
   - Parse `--env local|staging`. **If the env is anything else (including `production`), print an error and exit 1.**
   - Build one SQL file `seed/.generated.sql` (git-ignored) that first deletes all rows in FK-safe order (`download_tokens, orders, claim_attempts, payments, raw_sms, manual_versions, car_models`), then inserts:
     - `byd-e2-2025` "BYD E2" model_year "2025", sort 1, visible
     - `byd-sealion-2026` "BYD Sealion" "2026", sort 2, visible
     - `byd-dolphin-2025` "BYD Dolphin" "2025", sort 3, visible, **with a version but no `r2_key`** (shows "coming soon", FR-3)
     - `byd-han-2024` "BYD Han" "2024", sort 4, **hidden** (`is_visible=0`)
     - one `en` version per model at `price_santim = 50000`; E2 and Sealion get `r2_key = "manuals/<slug>-en-demo.pdf"` and a `file_size`.
   - Export a `SEED_SECTIONS` array of SQL-builder functions so later tasks (P1-SEED, P2-SEED, P3-SEED) can append sections without rewriting the file.
   - Generate a small valid placeholder PDF per manual (hand-written minimal PDF 1.4 bytes with one page of text "DEMO — <name> (<year>) owner's manual"). Write it to `seed/.pdf/<slug>-en-demo.pdf` (git-ignored) and upload it with `wrangler r2 object put <bucket>/<key> --file <path> --content-type application/pdf --local|--remote [--env staging]`. Buckets: `byd-manuals-dev` (local), `byd-manuals-staging` (staging).
   - Run `wrangler d1 execute DB --file seed/.generated.sql --local|--remote [--env staging]`.
   - Use `execFileSync("pnpm", ["wrangler", ...], { stdio: "inherit" })`; fail loudly on any error.
2. `seed/.gitignore` containing `.generated.sql` and `.pdf/`.

## Acceptance criteria
- `pnpm db:reset:local && pnpm seed:local` succeeds twice in a row (idempotent).
- After seeding: 4 car models, 4 manual versions, 2 PDFs in local R2.
- `tsx scripts/seed.ts --env production` exits 1 without running any wrangler command.

## Tests to write or update
- None (script). The behaviour is verified by the P1 E2E run, which seeds through `e2e:server`.

## How to test manually
1. `pnpm db:reset:local && pnpm seed:local`
2. `pnpm wrangler d1 execute DB --local --command "SELECT slug, is_visible FROM car_models"` → 4 rows.
3. `pnpm wrangler r2 object get byd-manuals-dev/manuals/byd-e2-2025-en-demo.pdf --local --file /tmp/e2.pdf` and open `/tmp/e2.pdf` → a one-page demo PDF.
4. `pnpm tsx scripts/seed.ts --env production` → error, exit code 1.
