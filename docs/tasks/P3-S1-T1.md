## Context
`POST /api/claim` has a `// P3-S1-T1: turnstile + rate limit` hook before validation. `claim_attempts(ip, created_at)` is indexed. Polls (`GET /api/claim/status`) are authorized by the signed ticket and must **not** require Turnstile. Turnstile test keys: site `1x00000000000000000000AA` (always passes), secret `1x0000000000000000000000000000000AA` (already in `.dev.vars.example`); always-fail secret `2x0000000000000000000000000000000AA`.

## Do this
1. Var `TURNSTILE_SITE_KEY` in all three envs (test site key for local/staging; placeholder for production), plus `RATE_LIMIT_MAX` ("10") and `RATE_LIMIT_WINDOW_MINUTES` ("10"). Run `pnpm cf-typegen`.
2. `src/lib/turnstile.ts`: `verifyTurnstile(secret, token, ip)` → POST `https://challenges.cloudflare.com/turnstile/v0/siteverify` (form-encoded `secret`, `response`, `remoteip`); return `success`; treat network errors as failure.
3. `src/lib/rate-limit.ts`: `clientIp(c)` → `CF-Connecting-IP`; **only when `ENVIRONMENT === "development"`**, prefer an `X-Test-Client-IP` header if present (E2E tests run every claim from localhost and would otherwise rate-limit each other). `isRateLimited(db, ip, now, max, windowMs)` → `SELECT COUNT(*) FROM claim_attempts WHERE ip=? AND created_at>?` (indexed).
4. In `POST /api/claim`, in this order: rate limit → `429 {status:"error", code:"RATE_LIMITED"}`; then Turnstile (`turnstileToken` in the body) → `403 {status:"error", code:"BOT_CHECK_FAILED"}`. Both cases write a `claim_attempts` row.
5. `checkout.tsx`: load `https://challenges.cloudflare.com/turnstile/v0/api.js?render=explicit` (async, defer); render the widget into `#turnstile-slot` with `data-sitekey`.
6. `claim.js`: wait for the Turnstile token before enabling submit; send `turnstileToken`; after every POST, call `turnstile.reset()` so a retry gets a fresh token. The poller is unchanged.

## Acceptance criteria
- The 11th POST from one IP within 10 minutes → `RATE_LIMITED`, even with valid input; a different IP is unaffected; after the window passes, it's allowed again (PRD security).
- A missing or invalid Turnstile token → `BOT_CHECK_FAILED`; nothing else is evaluated.
- Polling with a valid ticket works without Turnstile and is not rate-limited.
- `X-Test-Client-IP` is ignored when `ENVIRONMENT` is `staging` or `production`.
- The checkout page shows the Turnstile widget; a buyer can submit twice in a row (the token resets).
- All existing claim tests pass (update them to send a test token and stub `siteverify`).
