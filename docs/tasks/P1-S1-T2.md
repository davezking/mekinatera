## Why this model / review tier
Sonnet: the schema is fully specified below; the work is careful transcription plus constraint tests.
Opus review: this is the core data model of the money path, and a missing UNIQUE or CHECK constraint here is how a PDF gets released twice.

## Context
Scaffold exists (P1-S1-T1). Money is integer santim and time is integer Unix ms UTC (see `CLAUDE.md`). Every hot-path lookup needs an index.

## Do this
Create `migrations/0001_init.sql` with exactly these tables (all `id INTEGER PRIMARY KEY AUTOINCREMENT`, all `*_at INTEGER`, booleans `INTEGER NOT NULL DEFAULT …` with `CHECK (x IN (0,1))`). Declare `REFERENCES` on every foreign key (D1 enforces foreign keys by default, so no PRAGMA is needed).

- `car_models`: `name TEXT NOT NULL`, `slug TEXT NOT NULL UNIQUE`, `model_year TEXT NOT NULL`, `image_key TEXT`, `is_visible` (default 1), `sort_order INTEGER NOT NULL DEFAULT 0`, `created_at`, `updated_at` (NOT NULL).
- `manual_versions`: `car_model_id` FK, `language TEXT NOT NULL DEFAULT 'en' CHECK (language IN ('en','am'))`, `price_santim INTEGER NOT NULL CHECK (price_santim > 0)`, `r2_key TEXT`, `file_size INTEGER`, `is_visible` (default 1), timestamps; `UNIQUE (car_model_id, language)`.
- `raw_sms`: `sender TEXT NOT NULL`, `body TEXT NOT NULL` (always stored redacted), `received_at INTEGER NOT NULL`, `parse_status TEXT NOT NULL CHECK (parse_status IN ('parsed','ignored','failed'))`, `pattern_id TEXT`, `created_at`. Index `(parse_status, received_at)`.
- `payments`: `transaction_number TEXT NOT NULL UNIQUE CHECK (length(transaction_number)=10)`, `amount_santim INTEGER NOT NULL CHECK (amount_santim > 0)`, `payer_name TEXT NOT NULL`, `payer_phone_masked TEXT NOT NULL`, `paid_at INTEGER NOT NULL`, `raw_sms_id` FK → raw_sms, `status TEXT NOT NULL DEFAULT 'unclaimed' CHECK (status IN ('unclaimed','claimed','flagged'))`, `claimed_at INTEGER`, `claim_ref TEXT UNIQUE`, `flag_reason TEXT`, `created_at`. Index `(status, paid_at)`.
- `orders`: `payment_id` FK → payments, `UNIQUE` (nullable), `manual_version_id` FK NOT NULL, `created_by TEXT NOT NULL CHECK (created_by IN ('auto','admin'))`, `admin_note TEXT`, `created_at`.
- `download_tokens`: `order_id` FK NOT NULL, `token_hash TEXT NOT NULL UNIQUE`, `expires_at INTEGER NOT NULL`, `max_downloads INTEGER NOT NULL`, `download_count INTEGER NOT NULL DEFAULT 0`, `revoked_at INTEGER`, `created_at`. Index `(order_id)`.
- `claim_attempts`: `transaction_number_input TEXT NOT NULL`, `manual_version_id INTEGER`, `ip TEXT NOT NULL`, `result_code TEXT NOT NULL`, `created_at`. Index `(ip, created_at)`.

Create `src/lib/db/types.ts` with one row type per table (`CarModelRow`, `ManualVersionRow`, `RawSmsRow`, `PaymentRow`, `OrderRow`, `DownloadTokenRow`, `ClaimAttemptRow`) plus string-union types `ParseStatus`, `PaymentStatus`, `OrderCreatedBy`.

## Acceptance criteria
- `pnpm db:reset:local` applies the migration cleanly.
- Inserting two payments with the same `transaction_number` fails (FR-9).
- Inserting two orders with the same non-null `payment_id` fails; two orders with `payment_id NULL` succeed.
- Invalid enum values (`status='paid'`, `parse_status='x'`, `language='fr'`) are rejected by CHECK constraints.
- `EXPLAIN QUERY PLAN` for `SELECT * FROM payments WHERE transaction_number=?` and `SELECT * FROM download_tokens WHERE token_hash=?` uses an index (not `SCAN`).

## Tests to write or update
- `test/schema.test.ts`: the uniqueness, nullable-unique and CHECK cases above, plus the two `EXPLAIN QUERY PLAN` assertions (the plan detail contains `USING INDEX` or `USING COVERING INDEX`, and no `SCAN payments`/`SCAN download_tokens`).

## How to test manually
1. `pnpm db:reset:local`
2. `pnpm wrangler d1 execute DB --local --command "SELECT name FROM sqlite_master WHERE type IN ('table','index') ORDER BY name"` → all tables and indexes listed.
3. Run `INSERT INTO raw_sms(sender,body,received_at,parse_status,created_at) VALUES('127','x',0,'parsed',0)`, then insert the same payment `transaction_number` twice → the second insert fails with UNIQUE constraint.
