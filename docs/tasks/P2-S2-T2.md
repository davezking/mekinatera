## Why this model / review tier
Sonnet: small feature across an endpoint, a migration, the dashboard and a guide.
Auto: same secret check as the reviewed webhook; no payment logic.

## Context
`safeEqual` is in `src/lib/secrets.ts`. The `heartbeatRoutes` stub is mounted at `/api/heartbeat`. The admin layout has `<div id="status-banner">`; the dashboard is in `src/routes/admin.tsx`. "No SMS" can just mean "no sales", so phone health comes from a periodic heartbeat (MacroDroid, every 30 min). The last SMS time is still shown for context (FR-27).

## Do this
1. `migrations/0002_system_status.sql`: `system_status(key TEXT PRIMARY KEY, value TEXT NOT NULL, updated_at INTEGER NOT NULL)`.
2. `POST /api/heartbeat`: `X-Webhook-Secret` check (401 otherwise); upsert `last_heartbeat_at = now` (and `battery` if a numeric 0–100 is sent); 200 `{ok:true}`.
3. Var `HEARTBEAT_STALE_MINUTES` ("45") in all envs of `wrangler.admin.jsonc` (only the admin Worker reads it); add it to `AdminBindings` in `src/admin-env.ts`. The heartbeat endpoint itself stays on the public Worker (the phone posts there).
4. `src/lib/heartbeat.ts`: `getPhoneStatus(db, now)` → `{lastHeartbeatAt, lastSmsAt, battery, state: "ok" | "stale" | "never"}`, where `lastSmsAt = MAX(received_at)` of `raw_sms` (indexed).
5. Admin: render `status-banner.tsx` on every admin page via `admin.tsx` (pass it into the layout's banner slot): a green line "Phone online · last check-in 12 min ago · last SMS 3 h ago · battery 80%", or a red banner "Phone has not checked in for 2 h 5 min. Payments will not verify automatically. Check the phone." Also show it on the dashboard.
6. `docs/phone-setup.md`: step-by-step for the owner:
   - SMS forwarder app install and settings: sender filter `127`, URL `https://byd-manuals.<account>.workers.dev/api/sms-webhook` (production; staging uses `byd-manuals-staging…`; replace with the custom domain if one is added later), header `X-Webhook-Secret`, JSON template `{"from":"%from%","body":"%text%","receivedAt":"%receivedStamp%"}`, retry on failure.
   - MacroDroid macro: trigger every 30 min → HTTP request POST `/api/heartbeat` with the header and body `{"battery": [battery]}`.
   - Phone settings: disable battery optimization for both apps, keep on charge, mobile data + Wi-Fi, auto-start allowed (brand-specific notes for Tecno/Infinix/Samsung).
   - The 48-hour soak test and how to read the banner.

## Acceptance criteria
- Heartbeat with a wrong secret → 401; with the right secret → the banner shows "online" (FR-27).
- No heartbeat for more than `HEARTBEAT_STALE_MINUTES` → red banner on every admin page.
- Never received → "Phone has never checked in" (red).
- The last SMS time shows the newest `raw_sms`.
- `docs/phone-setup.md` covers the forwarder, the heartbeat, battery settings and the soak test.

## Tests to write or update
- `test/heartbeat.test.ts`: auth, upsert, the `getPhoneStatus` states with a fixed `now`, and the banner text in `/admin` HTML (via `adminFetch`).

## How to test manually
1. `pnpm db:reset:local`, then `pnpm dev` and `pnpm dev:admin` → http://localhost:8788/admin shows the red "never checked in" banner.
2. `curl -X POST localhost:8787/api/heartbeat -H 'X-Webhook-Secret: dev-webhook-secret' -H 'content-type: application/json' -d '{"battery":80}'` → the banner turns green with battery 80%.
3. Set `HEARTBEAT_STALE_MINUTES` to "0" locally → red banner. Revert.
