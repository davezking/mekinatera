## Why this model / review tier
Sonnet: read-only list pages with filters and pagination.
Opus review: these are the only pages that show payer names and phone numbers (personal data).

## Context
Admin auth and layout exist on the separate admin Worker (dev: `pnpm dev:admin` on :8788). Test admin routes with `adminFetch` from `test/helpers/admin.ts`; public pages with `SELF`. Stubs `/admin/payments` and `/admin/orders` exist; this task implements the list pages under `/admin/payments` (payments, SMS) and **only the list view** of orders inside `payments.tsx` routes at `/admin/payments/orders`. `/admin/orders` (stub) is for actions in P2-S2-T3. Indexes: `payments(status, paid_at)`, `raw_sms(parse_status, received_at)`.

## Do this
1. `src/lib/db/admin-queries.ts`: `listPayments(db, {status?, before?, limit=50})` using keyset pagination on `paid_at`; `getPayment(db, id)` with its raw SMS and order (if any); `listSms(db, {parseStatus, before?, limit})`; `listOrders(db, {before?, limit})` joined with version, model, payment txn, and the newest token's `download_count/max_downloads/expires_at/revoked_at`.
2. `GET /admin/payments?status=all|unclaimed|claimed|flagged`: tabs; columns: paid at (shown in EAT), txn, amount (ETB), payer name, masked phone, status, flag reason, link to detail (FR-25).
3. `GET /admin/payments/:id`: all fields + the redacted raw SMS + order and token status. Leave a `<section id="actions">` placeholder for P2-S2-T3.
4. `GET /admin/payments/sms?status=failed|ignored`: redacted SMS bodies with received time and pattern (FR-7 admin visibility).
5. `GET /admin/payments/orders`: orders list with created_by, txn (or "manual"), model, downloads used, link status (active / expired / used up / revoked) (FR-25).
The admin nav already links to these three URLs (P2-S1-T1).

## Acceptance criteria
- Each status tab shows only matching payments, newest first, 50 per page with a "Older" link (FR-25).
- Payment detail shows the redacted SMS (no balance) and the linked order, if any.
- The failed/ignored SMS list shows seeded rows (FR-7).
- The orders list shows `DEMOUSED01`'s order with "1/3 downloads".
- Payer names and phones appear only under `/admin` (a public-page grep test).
- All list queries use an index (assert with `EXPLAIN QUERY PLAN` in the test for the payments list).

## Tests to write or update
- `test/admin-lists.test.ts`: filters, pagination boundary, detail page content, the EXPLAIN check, and a test that `/`, `/m/*` and `/api/models` never contain seeded payer names.

## How to test manually
1. `pnpm db:reset:local && pnpm seed:local`, then `pnpm dev` and `pnpm dev:admin`
2. http://localhost:8788/admin/payments → 9 demo payments; the Flagged tab is empty until you claim `DEMOLOW001` on the public site, then it shows it.
3. Open `DEMOPAY001` → detail with the redacted SMS.
4. `/admin/payments/sms?status=failed` → the garbage SMS; `?status=ignored` → the bank SMS.
5. `/admin/payments/orders` → `DEMOUSED01` order, 1/3 downloads.
