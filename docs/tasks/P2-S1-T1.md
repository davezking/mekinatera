## Why this model / review tier
Opus: this creates a second deployable Worker and the auth boundary for everything that can release PDFs manually or show personal data. JWT verification has subtle failure modes.
Opus review: auth + core architecture.

## Context
Phase 1 is merged. There is no custom domain, so admin runs as a **separate Worker** on its own `workers.dev` address. Cloudflare Access is switched on for that whole address (Workers → admin Worker → Settings → Domains & Routes → workers.dev → Cloudflare Access). The public Worker (`wrangler.jsonc`, `src/index.ts`) has no admin code and must stay that way. Both Workers share the same D1 database and R2 bucket in each environment. Access adds a `Cf-Access-Jwt-Assertion` header; the Worker must verify it anyway (defense in depth). Local dev uses the bypass described in `architecture.md` §6.

## Do this
1. **`wrangler.admin.jsonc`**: `name: "byd-manuals-admin-dev"`, `main: "src/admin-worker.ts"`, same `compatibility_date`/flags as `wrangler.jsonc`, `assets: { directory: "./public", binding: "ASSETS" }`, `workers_dev: true`, `preview_urls: false`, `observability: { enabled: true }`. Top level, `env.staging` (`byd-manuals-admin-staging`) and `env.production` (`byd-manuals-admin`) each repeat **the same `DB` and `MANUALS` bindings (same database_id / bucket) as the matching env in `wrangler.jsonc`**. Vars: everything the public Worker has (shared code reads them, e.g. `TOKEN_TTL_HOURS`, `SUPPORT_CONTACT`), plus `ACCESS_TEAM_DOMAIN`, `ACCESS_AUD`, `ADMIN_EMAIL`. Add a top-of-file comment: "Bindings must match wrangler.jsonc for the same env."
2. **`src/admin-env.ts`**: `type AdminBindings = Env & { ACCESS_TEAM_DOMAIN: string; ACCESS_AUD: string; ADMIN_EMAIL: string; ADMIN_DEV_BYPASS?: string }`, `type AdminEnv = { Bindings: AdminBindings; Variables: { adminEmail: string } }`. (Keep `wrangler types` generated from `wrangler.jsonc` only; this avoids two conflicting global `Env` types.)
3. **`src/admin-worker.ts`**: Hono app: `GET /` → redirect to `/admin`; `GET /healthz`; mount `adminRoutes` at `/admin`; everything else → 404. Export the app as default and as named `adminApp` (for tests).
4. Add dependency `jose`. Scripts: `dev:admin` = `wrangler dev -c wrangler.admin.jsonc --port 8788`; `e2e:admin-server` = `wait-on http://localhost:8787/healthz && pnpm dev:admin` (add `wait-on` dev dep). Both dev servers share local D1/R2 state in `.wrangler/state` because the binding ids match.
5. **`playwright.config.ts`**: `webServer` becomes an array: the existing public server, plus the admin server (`pnpm e2e:admin-server`, url `http://localhost:8788/healthz`). Export `ADMIN_URL = "http://localhost:8788"` for specs.
6. **`src/middleware/admin-auth.ts`** → `adminAuth()`:
   - **Dev bypass** only when `ENVIRONMENT === "development"` **and** `ADMIN_DEV_BYPASS === "1"` **and** hostname is `localhost`/`127.0.0.1`. Set `adminEmail = "dev@localhost"`.
   - Otherwise read the JWT from `Cf-Access-Jwt-Assertion` (fallback `CF_Authorization` cookie). `jwtVerify(token, createRemoteJWKSet(new URL(ACCESS_TEAM_DOMAIN + "/cdn-cgi/access/certs")), { issuer: ACCESS_TEAM_DOMAIN, audience: ACCESS_AUD })`, JWKS cached per isolate.
   - Require `payload.email` (case-insensitive) `=== ADMIN_EMAIL`. Any failure → 403 "Not authorized" and log `{event:"admin_denied", reason}`.
   - Non-GET/HEAD: `Origin` must equal the request origin, otherwise 403 (CSRF).
   - Every response: `Cache-Control: no-store`, `X-Robots-Tag: noindex, nofollow`.
7. **`src/routes/admin.tsx`** (new file, `Hono<AdminEnv>`): `adminAuth()` on `*`; stub sub-routers `src/routes/admin/{catalog,uploads,payments,orders}.tsx` mounted at `/catalog`, `/uploads`, `/payments`, `/orders`; `GET /` → dashboard.
8. **`src/views/admin/layout.tsx`**: nav (Dashboard `/admin` · Catalog `/admin/catalog` · Payments `/admin/payments` · SMS `/admin/payments/sms` · Orders `/admin/payments/orders`), the signed-in email, a `<div id="status-banner">` slot (filled by P2-S2-T2), and a "View public site" link built from a `PUBLIC_SITE_URL` var (add it to all envs in `wrangler.admin.jsonc`).
9. **`src/views/admin/dashboard.tsx`**: counts for today and all time: payments received / claimed / unclaimed / flagged, orders, failed SMS (index-backed `COUNT(*)`).
10. **`test/helpers/admin.ts`**: `adminFetch(path, init?, envOverrides?)` → `adminApp.request(path, init, { ...env, ACCESS_TEAM_DOMAIN, ACCESS_AUD, ADMIN_EMAIL, ADMIN_DEV_BYPASS: "1", ...envOverrides })`, using `env` from `cloudflare:test` (same DB/R2). Later admin tasks use this helper.
11. `.dev.vars.example`: make sure `ADMIN_DEV_BYPASS=1` is there with a comment that it only works on localhost in development.

## Acceptance criteria
- Non-development env: no JWT, wrong `aud`/`iss`, expired JWT, or another email → 403; a valid JWT for `ADMIN_EMAIL` → 200 (FR-23).
- The dev bypass works only for development + flag + localhost (all three).
- A POST with a foreign `Origin` → 403.
- Every admin response has `no-store` and `noindex`.
- The **public** Worker returns 404 for `/admin` and `/admin/anything` (tested via `SELF`).
- `pnpm dev` + `pnpm dev:admin` together: the admin dashboard on :8788 shows counts from the data seeded for :8787.
- The dashboard counts match the seeded data.

## Tests to write or update

## How to test manually
1. `pnpm db:reset:local && pnpm seed:local`, then `pnpm dev` and `pnpm dev:admin` in two terminals.
2. http://localhost:8788/admin → dashboard with counts. http://localhost:8787/admin → 404.
3. On staging after deploy: open `https://byd-manuals-admin-staging.<account>.workers.dev/admin` → Access login (email code) → dashboard. In a private window, `curl -i` the same URL → redirect to the Access login, never the dashboard.
