## Why this model / review tier
Sonnet: the checklist has to be complete and in the right order; a missed step means a broken launch.
Auto: config and docs; production deploy itself is gated by a manual approval environment.

## Context
`deploy-staging.yml` shows the pattern (wrangler-action, migrations then deploy). Production deploys only from tags `v*` on `main`. The production Worker is `byd-manuals`; bindings are in `wrangler.jsonc` `env.production`. The PRD rollout: 1 ETB test → soft launch to 1–2 Telegram groups → 30-day review. Phone setup is in `docs/phone-setup.md`.

## Do this
1. `.github/workflows/deploy-production.yml`: on push of tags `v*`; job `environment: production` (configure required reviewers in GitHub so it waits for your click); verify the tag's commit is on `main` (`git merge-base --is-ancestor $GITHUB_SHA origin/main`); run lint/typecheck/test; `d1 migrations apply DB --env production --remote`; `deploy --env production`; `deploy -c wrangler.admin.jsonc --env production`. **No seeding.**
2. `docs/launch-checklist.md`, ordered checkboxes with exact commands:
   - Cloudflare: create production D1 + R2 (`wrangler d1 create byd-manuals`, `wrangler r2 bucket create byd-manuals`), put IDs in `wrangler.jsonc`; confirm the R2 bucket has no public access/r2.dev URL; secrets via `wrangler secret put --env production` (WEBHOOK_SECRET, TICKET_SECRET, TURNSTILE_SECRET_KEY — new random values, never reused from staging); vars in **both** `wrangler.jsonc` and `wrangler.admin.jsonc` (confirm production `TELEBIRR_PHONE` 0977328406, `TELEBIRR_NAME` "Dawit As****" exactly as telebirr shows it to payers, `SUPPORT_CONTACT` mailbox works (send a test email), `ADMIN_EMAIL`, `ACCESS_*`, `PUBLIC_SITE_URL`, real `TURNSTILE_SITE_KEY`); enable Cloudflare Access on the production admin Worker's `workers.dev` address with a policy for your email only, and copy its AUD tag into `ACCESS_AUD`; confirm the public Worker's `workers.dev` address has Access **off**; Turnstile widget with the public `workers.dev` hostname; usage notifications at 80% of free limits; re-check free-plan limits (PRD risk 11).
   - Optional, later: custom domain. Buy it on Cloudflare, attach it to the public Worker as a Custom Domain, add it to the Turnstile widget and update the forwarder/MacroDroid URLs. The admin Worker can stay on `workers.dev`.
   - Content: upload the real E2 and Sealion PDFs and images via admin; check prices.
   - Phone: follow `docs/phone-setup.md` with the production URL and secret; 48-hour soak (heartbeat stays green; a test transfer arrives).
   - **Gate:** a real transfer from a friend's phone confirms the buyer sees the same transaction number as the owner's SMS (PRD Q1b). Do it with a temporary visible "Test product" at 1 ETB (create in admin, upload any PDF, hide it afterwards).
   - Go live: unhide the catalog, post in 1–2 Telegram groups, note the date for the 30-day review, and list the metrics to pull (paid orders, auto vs admin orders, payment→claim time, support requests).
3. `docs/runbook.md`: short procedures: buyer says "I paid but it doesn't work" (check payments by txn, flagged, ignored SMS, manual approve); phone offline (red banner); link expired (regenerate); bank-app payment (manual order or refund); refund (manual, outside the system, add an admin note); webhook secret leaked (rotate in Cloudflare + forwarder app + MacroDroid); new SMS wording appears in Failed SMS (add a pattern in `src/lib/sms/patterns.ts` + test, then deploy); approaching free limits.

## Acceptance criteria
- The production workflow only runs on `v*` tags, refuses tags not on `main`, waits for environment approval, and never seeds.
- The launch checklist covers every item above with copy-pasteable commands, in order, including the Q1b gate.
- The runbook covers all eight situations.

## Tests to write or update
- None (workflow + docs). Validate the YAML with `actionlint` if available, or note it in the PR.

## How to test manually
1. Read `docs/launch-checklist.md` top to bottom and confirm every step is something you can do without asking.
2. In GitHub → Settings → Environments, create `production` with yourself as required reviewer. Push a test tag on a non-main commit → the workflow fails at the ancestor check.
