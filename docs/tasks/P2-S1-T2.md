## Why this model / review tier
Sonnet: standard CRUD with validation, server-rendered forms.
Auto: behind admin auth (already reviewed); no payment logic.

## Context
`adminAuth` protects `/admin/*` on the separate admin Worker (`src/admin-worker.ts`, dev on :8788 via `pnpm dev:admin`; the public site stays on :8787). Test admin routes with `adminFetch` from `test/helpers/admin.ts`. The `/admin/catalog` stub exists. Public read queries are in `src/lib/db/catalog.ts`; add write helpers there. Money helpers are in `src/lib/money.ts`. Uploads come in P2-S1-T3. Leave a `<section id="uploads">` placeholder on the edit page.

## Do this
1. `GET /admin/catalog`: a table of all models (including hidden) with year, visible, sort, price, PDF status (uploaded / missing), and an Edit link. "Add model" button.
2. `GET /admin/catalog/new` and `POST /admin/catalog`: fields name, slug (auto-suggested from name client-side, editable, `^[a-z0-9-]{3,60}$`, unique), model year (free text, max 20), sort order, visible. Creating a model also creates its `en` version with a price (required).
3. `GET /admin/catalog/:id` and `POST /admin/catalog/:id`: edit the same fields plus price (ETB input → `etbToSantim`, must be > 0 and ≤ 100,000 ETB) and version visible. Language is shown as "English" (read-only).
4. Validation errors re-render the form with messages and the entered values. Success → redirect to the list with a flash message (query param `?saved=1` is fine).
5. Write helpers in `src/lib/db/catalog.ts`: `createModelWithVersion`, `updateModel`, `updateVersion` (set `updated_at`). Use a `batch` for create.

## Acceptance criteria
- The admin can create a model with a price, and it appears on the public catalog as "Coming soon" until a PDF is uploaded (FR-24, FR-3).
- The admin can change the price; the checkout page shows the new price immediately (FR-2).
- Hiding a model removes it from `/` and makes `/m/<slug>` return 404.
- A duplicate slug, invalid slug, empty name, or a price ≤ 0 or non-numeric shows a form error and saves nothing.
- Forms work without JavaScript.

## Tests to write or update
- `test/admin-catalog.test.ts`: create, edit price, hide/unhide, and validation failures (via `adminFetch`, with `Origin` set to the test origin; public-page checks via `SELF`).

## How to test manually
1. `pnpm dev` and `pnpm dev:admin` → http://localhost:8788/admin/catalog.
2. Add "BYD Atto 3", year "2025", price 450 → the public catalog shows it as Coming soon.
3. Edit the Sealion price to 600 → `/m/byd-sealion-2026` shows 600 ETB. Set it back to 500.
4. Uncheck Visible on E2 → it disappears from `/`. Re-check it.
5. Try slug `BAD SLUG!` → form error.
