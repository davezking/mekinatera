## Why this model / review tier
Sonnet: a single endpoint with a clear spec.
Opus review: an authenticated entry point that creates payments. The secret check, sender filter and idempotency are security-critical.

## Context
`parseTelebirrSms` and `redactSms` exist in `src/lib/sms/`. `webhookRoutes` is mounted at `/api/sms-webhook`. Secret `WEBHOOK_SECRET` (dev: `dev-webhook-secret`). The forwarder app posts `{"from":"…","body":"…","receivedAt":"…"}`, where `receivedAt` may be epoch ms (string or number) or ISO.

## Do this
1. `src/lib/secrets.ts`: `safeEqual(a: string, b: string): boolean` using `crypto.subtle.timingSafeEqual` on UTF-8 bytes (returns false on length mismatch, without throwing).
2. `POST /api/sms-webhook` in `src/routes/webhook.ts`:
   - Missing or wrong `X-Webhook-Secret` → 401 `{error:"unauthorized"}`; nothing stored.
   - Body is not JSON, or `body` is missing → 400.
   - `from.trim() !== "127"` → 200 `{result:"discarded"}`; **nothing stored** (FR-7).
   - Otherwise parse `receivedAt` (fallback: now). Run `parseTelebirrSms(body)`. Insert `raw_sms` with `redactSms(body)`, `parse_status` and `pattern_id` (`INSERT … RETURNING id`).
   - On `kind: "payment"`: `INSERT INTO payments (…) VALUES (…) ON CONFLICT(transaction_number) DO NOTHING`. Return `{result:"stored"}`, or `{result:"duplicate"}` if 0 rows changed (FR-9).
   - On `ignored` / `failed` → 200 `{result:"ignored"|"failed"}`.
   - Always 200 for authenticated, well-formed requests, so the forwarder doesn't retry forever.
   - Log `{event:"sms_received", result, patternId, rawSmsId}` only. No body, name or phone.
3. `src/lib/db/payments.ts`: `insertRawSms(db, row)`, `insertPaymentIfNew(db, row): Promise<boolean>`, `getPaymentByTxn(db, txn)`.

## Acceptance criteria
- Wrong or missing secret → 401, and no row in any table.
- Sender `127` + the appendix SMS → 200 `stored`; one `raw_sms` row (`parsed`, body without the balance) and one `payments` row with status `unclaimed`, the correct amount and `paid_at` (FR-6, FR-8, FR-10).
- The same request twice → the second returns `duplicate`; still one payment (FR-9).
- Sender `+251911…` with the same body → `discarded`; zero rows (FR-7).
- A bank-deposit style message from 127 → `raw_sms.parse_status = 'ignored'`, no payment (FR-7).
- Unparseable text from 127 → `failed`, stored for admin, no payment.
- Logs contain no payer name, phone or SMS body.

## Tests to write or update
- `test/webhook.test.ts`: every acceptance criterion via `SELF.fetch`, including asserting row counts.
- `test/secrets.test.ts`: equal, unequal, different-length cases.

## How to test manually
1. `pnpm dev` (with `.dev.vars`).
2. Run:
   `curl -s -X POST localhost:8787/api/sms-webhook -H 'X-Webhook-Secret: dev-webhook-secret' -H 'content-type: application/json' -d '{"from":"127","body":"You have received ETB 500.00 from Abebe Kebede(2519****2531) on 26/09/2026 09:57:24. Your transaction number is TESTTXN001. Your current E-Money Account balance is ETB 1,234.00.","receivedAt":"1790000000000"}'` → `{"result":"stored"}`.
3. Run it again → `{"result":"duplicate"}`.
4. Run it with a wrong secret → 401.
5. `pnpm wrangler d1 execute DB --local --command "SELECT transaction_number, amount_santim, status FROM payments; SELECT body FROM raw_sms"` → one payment of 50000; the body shows `balance is ETB [redacted]`.
